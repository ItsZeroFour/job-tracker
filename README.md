# Job Tracker

Трекер откликов на вакансии. Приложение помогает вести список откликов: в какую компанию и на какую позицию откликнулся, на каком этапе процесс (отклик, скрининг, интервью, оффер, отказ) и что делать дальше.

## Возможности

- Список откликов с поиском по компании, фильтром по статусу и пагинацией.
- Создание, редактирование и удаление отклика.
- Смена статуса с оптимистичным обновлением и откатом при ошибке сервера.
- Состояния загрузки, ошибки и пустого списка.

## Стек

| Область | Инструменты |
|---|---|
| UI | React, TypeScript (strict), Vite |
| Данные с сервера | TanStack Query v5 |
| Маршрутизация | React Router |
| Формы | React Hook Form |
| Тесты | Vitest, React Testing Library, user-event |
| Архитектура | Feature-Sliced Design (FSD) |

«Сервер» имитируется функциями на промисах с искусственной задержкой и случайными ошибками. Данные берутся из JSON-файла (`applications.seed.json`, 45 записей).

## Структура проекта (FSD)

```
src/
  app/        провайдеры (QueryProvider, роутер), глобальные стили
  pages/      страницы (список, детали, редактирование)
  widgets/    составные блоки (таблица откликов с фильтрами)
  features/   пользовательские действия (смена статуса, форма, удаление)
  entities/   сущности и чтение данных (applications: типы, api, хуки, ui)
  shared/     переиспользуемое (ui-кит, утилиты)
  test/       настройка тестов и общие утилиты
```

Импорты идут только вниз по слоям: `app → pages → widgets → features → entities → shared`.

## Запуск

Нужен Node.js 22.12+ (или 20.19+).

```bash
npm install
npm run dev      # режим разработки
npm run build    # production-сборка
npm run test     # тесты (Vitest, режим наблюдения)
```

## Принятые решения

- **TanStack Query вместо Redux.** Данные с сервера это server state: им нужны кэш, дедупликация запросов и статусы загрузки. Query даёт это из коробки, а глобальный клиентский стейт здесь почти не нужен.
- **Чтение данных в `entities`, действия в `features`.** Сущность отдаёт и показывает данные, а изменяющие операции (мутации) относятся к пользовательским сценариям.
- **Тесты проверяют поведение.** Тестируется то, что видит пользователь. Мокается граница приложения (модуль с запросами), а хуки и компоненты работают настоящие. Для каждого теста создаётся новый `QueryClient` с `retry: false`.
- **Fake timers в тестах.** Искусственная задержка «сервера» не замедляет тесты: время прокручивается вручную.
